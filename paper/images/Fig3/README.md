# Fig. 3: GFMC throughput vs walker population

**Figure:** `images/Fig3.pdf` (`\label{fig:throughput}`).

Throughput, in GFMC iterations per second, as a function of the walker
population `N_walkers` for the one-dimensional Heisenberg chain at `L = 100`,
`n_bra = 6` and `λ = 25`. Blue: CPU runs (Intel Xeon Platinum 8480, 1–32
cores). Red: 1, 2 and 4 NVIDIA A100 (solid) and H200 (dashed) GPUs. Each point
is the mean of 10 independent runs.

## Data: `data.csv`

Plain CSV. The lines starting with `#` are a header that repeats this
description; `plot.py` skips them. One row per plotted point (171 rows).

| column | meaning |
|---|---|
| `device` | `CPU` (Intel Xeon Platinum 8480CL/8480+, Sapphire Rapids), `A100` (NVIDIA A100-SXM4-80GB) or `H200` (NVIDIA H200) |
| `n_devices` | number of CPU cores (`CPU`) or GPUs (`A100`, `H200`) |
| `n_walkers` | walker population `N_walkers` (powers of two, 2^10 … 2^24) |
| `it_per_sec_mean` | mean throughput over `n_runs` runs [iterations / s] |
| `it_per_sec_std` | sample standard deviation over the runs (ddof = 1) [iterations / s]; empty for H200 |
| `n_runs` | number of independent runs averaged (10, except 6 for CPU×16 at 2^18); empty for H200 |
| `source` | `measured` or `recovered_from_pdf` (see provenance) |

The figure plots `it_per_sec_mean` only; the standard deviation is kept for
reference and is not drawn.

## Benchmark setup

Spin-1/2 XXZ chain with `J_xy = −1`, `J_z = 1` (Heisenberg), `L = 100` sites,
periodic boundary conditions, no guiding wavefunction, Néel initial state,
`method = "single_step"`, `step_size (n_bra) = 6`, `λ = n_edges·J_z/4 = 25`.
Each run times 10 000 GFMC steps after 10 000 warm-up steps; the throughput is
`n_steps / elapsed_time`. Multi-GPU runs use the walker-sharded (`pmap`) path.
CPU runs were on one node of Sapphire Rapids nodes with the core count
restricted; GPU runs on 4-GPU nodes.

## Provenance

- **CPU and A100** (`source = measured`): aggregated (mean, std, count per
  `(device, n_devices, n_walkers)`) from the per-run benchmark table written by
  the benchmark driver used for the paper (not part of this package; one row
  per run, 10 repetitions per point).
- **H200** (`source = recovered_from_pdf`): the per-run H200 table was not
  available when this package was assembled. The means were read back from the
  vector line paths of the original, published `throughput.pdf` (generated by the
  original plotting script from those runs), using the axis tick positions as an
  exact log-scale calibration. The same procedure applied to the CPU and A100
  curves reproduces the measured means to a relative accuracy of 6e-8, so the
  H200 values carry the same precision. Standard deviations and run counts for
  H200 are therefore not available.
